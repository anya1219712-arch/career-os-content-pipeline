# Career OS · конвейер контента с ИИ

Прототип к ДЗ 3 курса «Маркетинг в цифровой среде» (Яндекс × ФКН, ИИМУП 26-28).
Команда: Мария Дудченко, Анна Платонова, Елизавета Астафьева, Денис Манаков.

Конвейер собирает черновики постов для Career OS — бота, который проверяет резюме по критериям практикующих рекрутеров. Механика показана на спецпроекте «Сломанный отклик», но та же схема работает для всей ленты: у каждой рубрики свой вход и промпт, шаги и проверки одинаковые.

| Рубрика | Вход | Площадки | Лимит в неделю |
|---|---|---|---|
| `slomanny_otklik` — «Сломанный отклик» | фрагмент резюме + «что сделал на самом деле», с согласия автора | TG, Threads, VK | 1 (слот «Почему не зовут») |
| `hr_eyes` — «Резюме глазами HR» | тема из контент-плана | TG, Threads, VK | 4 |
| `threads_reply` — ответы по Г3 | пост с просьбой о помощи | Threads | 10 (до 2 в будни) |

Общий лимит постов канала — 5 в неделю, по аудиту ДЗ 2.

## Как работает

```
бот: согласие + вопрос «что ты сделал на самом деле?»
  → обезличивание: правила (контакты, ссылки, компании, ФИО) → модель → контрольная проверка
  → отбор кейса под сегмент мидлов
  → черновик (модель выбирает факт опроса, программа подставляет его текст)
  → версии для TG / Threads / VK + ссылка с меткой ?start=<рубрика>_<площадка>
  → проверка: сначала правила, потом модель другого семейства
  → одна доработка с замечаниями; не прошло — к редактору с пометкой, утвердить нельзя
  → автор подтверждает текст про себя → редактор дописывает шутку и утверждает
  → выпуск встаёт в ближайшую неделю, где не превышены лимиты
```

**Выпуск не выходит, если** нет согласия, после обезличивания остались личные данные, в тексте цифра не из опроса или автор либо редактор против.

### Почему основная защита — правила, а не модель

- `app/facts.py` — белый список: только 4 реальные цифры опроса 10 практиков найма (ДЗ 1). Модель не пишет цифру сама, а выбирает ключ факта. Любая другая цифра «N из 10» или процент останавливает выпуск.
- `app/rules.py` — колонка «Не так» из ToV: давление временем («рекрутер смотрит N секунд»), обещание оффера, «HR Яндекса показала» и другие выдуманные истории (замечание к ДЗ 2), обязательная ссылка с меткой, лимит длины.
- `app/anonymize.py` — регулярные выражения работают до модели, поэтому контакты в модель не уходят.
- Вторая модель (`prompts/review.md`) ищет то, что правилами не поймать: приукрашивание опыта и насмешку над человеком. Это подстраховка, а не основной контроль: в нашем тесте нейросетей из ДЗ 2 GigaChat дописывал опыт, которого нет.

## Запуск

Нужен Python 3.11+.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate     macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

pytest                      # 14 тестов: правила, обезличивание, весь конвейер
python -m app.cli demo      # три рубрики на демо-данных, без ключей и Telegram
```

Без `LLM_API_KEY` модели заменяет детерминированная заглушка `MockLLM`: конвейер проходит все шаги, но тексты шаблонные. Для настоящих черновиков:

1. Скопируй `.env.example` в `.env`.
2. В панели Selectel → Token Factory выпусти API-ключ, поставь лимит расходов и впиши `LLM_BASE_URL` и `LLM_API_KEY`.
3. Создай бота у @BotFather, впиши `BOT_TOKEN`, id чата редакторов и id редакторов.
4. `python -m app.bot`

Команды бота: `/razbor` — поучаствовать в рубрике, `/otozvat` — отозвать согласие и удалить данные, `/queue` — очередь выпусков (для редакторов).

Карточки собираются по HTML-шаблону в цветах бренда (`app/templates/card.html`). Если установлен Playwright (`pip install playwright && playwright install chromium`), карточка сохраняется в PNG.

## Инфраструктура и бюджет

- **Модели:** Selectel Token Factory — инференс открытых моделей в дата-центрах РФ с оплатой за токены, OpenAI-совместимый API, без хранения запросов. Резерв — Cloud.ru или Yandex AI Studio (`LLM_FALLBACK_*`), переключение автоматическое.
- **Сервер:** облачный сервер Selectel, бот запускается как сервис (systemd или Docker).
- **База:** в прототипе SQLite, в проде PostgreSQL в Selectel. Схема в `app/db.py`.
- **Не используем:** Claude, ChatGPT и Grok через VPN или посредников (правила вендоров запрещают использование из РФ), OpenRouter (с мая 2026 не принимает платежи из РФ), Google Sheets для персональных данных.

Токены на одну единицу контента — порядка 1–2 ₽ (допущение по ценам Selectel на 23.10.2026). Основные расходы — сервер.

## Персональные данные (152-ФЗ)

- Отдельное согласие на анонимный разбор с понятным текстом, отзыв командой `/otozvat`: исходники стираются, черновики снимаются, редактор получает уведомление.
- Автор видит текст про себя до публикации, без его «да» выпуск не выходит.
- Обезличивание в два слоя и контрольная проверка следов.
- Кейсы хранятся и обрабатываются в РФ. Telegram остаётся каналом связи с пользователем.
- Исходники удаляются через `RETENTION_DAYS` (30 дней, ежедневная задача в 03:00).
- До запуска: уведомить Роскомнадзор об обработке ПД и опубликовать политику обработки в боте.

## Выбор моделей — гипотеза

Для обезличивания и версий под площадки, скорее всего, хватит дешёвой Qwen-3.8-Flash-Next. Для черновика сравниваем на 5 обезличенных кейсах Qwen-3.8-Flash-Next, Qwen-3.8-27B, DeepSeek-V4-Flash и GigaChat-2-Max по фактам, тону и юмору (оценка редактора 1–5). Берём самую дешёвую, что прошла порог, а не самую новую. Тест повторяем раз в квартал. Модели меняются в `.env`, код не трогаем.

## Пилот

10 единиц контента из разных рубрик: 5 собираем вручную, 5 через конвейер. Время шагов берём из таблицы `log`, правки — из статусов черновиков. Успех: конвейер быстрее хотя бы на треть, ошибок в фактах ноль.

```
  card.py        карточка по шаблону

  prompts/       промпты шагов
  templates/     шаблон карточки
data/demo_cases.json   вымышленные демо-кейсы
tests/                 pytest
```
